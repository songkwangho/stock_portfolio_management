# ADR-001 — 수정주가(adjusted price) 도입

- **상태**: 초안 (Phase 4 세션 3 §4 — 조사·설계까지. 마이그레이션은 별도 차수)
- **작성**: 2026-08-14
- **관련**: `phase4-krx-source-capability.md`(Step 0 실측) · 세션 2 분할 스크리닝 캐비엇

---

## 1. 맥락 — 이건 백테스트 편의가 아니라 라이브 correctness 문제다

`stock_history.price`는 **무수정 종가**다(네이버 `fchart` 원본, INTEGER). 액면분할·무상증자·주식배당이 일어나면 가격이 **하루에 기계적으로 튄다**. 2:1 분할은 −50%로 보인다.

이게 백테스트만의 문제였다면 표본에서 빼면 그만이다(세션 2가 그렇게 했다 — `loadCorporateActions` + 일일 제한폭 밖 급락 휴리스틱, 실측 15신호/2종목). 그런데 **같은 데이터가 라이브 화면을 그린다**:

| 표면 | 무수정 종가가 만드는 거짓 |
|---|---|
| `−7% 손절` 알림 (`calculateHoldingOpinion`) | 분할 당일 **거짓 발동** — 사용자에게 "[주의 필요]" 알림이 나간다 |
| 52주 범위·`positionPct` (StatsGrid 게이지, B차 `positionAnchor`) | 분할 전 가격이 그대로 남아 범위가 왜곡 → "범위 위쪽/아래쪽" 문구가 틀린다 |
| 포트폴리오 수익률·D차 기여 분해 | 평단은 사용자 입력(실제 체결가)인데 현재가 기준이 분할 전후로 섞인다 |
| `computeTechnicalFromHistory`(RSI·볼린저·MACD) | 분할일이 이상치로 들어가 지표가 며칠간 오염 |
| 세션 1·2 백테스트 | forward return 왜곡 |

특히 첫 줄이 무겁다. 이 앱은 판단을 최소화하고 관찰만 보여주는데, **거짓 관찰**은 그 원칙의 근간을 흔든다.

> **현재 노출 규모**: 세션 2 실측에서 178종목 3년 구간 중 분할 의심 **2종목 / 15신호**. 작지만 0이 아니고, 유니버스가 커질수록(디렉토리 ~2,650) 비례해 늘어난다.

## 2. 소스 현실 (Step 0 실측)

| 소스 | 수정주가 | 접근 |
|---|---|---|
| 네이버 `fchart` (현재 사용) | ❌ 무수정 | 무인증 |
| KRX Open API 일별매매정보 | ❌ 무수정(실제 체결가) | AUTH_KEY |
| **KRX MDC `MDCSTAT01701`** | ✅ `adjStkPrc=2` | **본인인증 회원 로그인 필요**(2026 변경) |

⇒ **수정주가를 얻는 유일한 경로는 KRX 회원계정이다.** 이 ADR의 실행 가능성이 그 결정에 묶여 있다.

## 3. 선택지

### A. 현행 유지 + 이벤트 마킹 (비용 최저)
`dart_disclosures`로 분할·증자 날짜를 알고 있으니, 그 날짜 전후 구간에 **플래그만** 세운다.
- 👍 신규 소스 0, 계정 0. 백테스트는 이미 이렇게 하고 있다.
- 👎 **라이브 숫자는 여전히 틀리다.** 52주 범위·손절 알림은 그대로 거짓. 플래그를 UI로 옮기면 "이 종목은 값이 이상할 수 있어요" 같은 변명이 되는데, 그건 고치는 게 아니라 사과하는 것이다.

### B. 조정계수 자체 계산 (중간)
분할 비율을 공시(`report_nm`)에서 파싱해 과거 가격에 소급 적용.
- 👍 신규 소스 0.
- 👎 비율 파싱이 자연어 의존이라 취약하고(무상증자율·병합비율 표기 제각각), **현금배당 조정은 불가**. 틀린 조정은 무조정보다 나쁘다 — 조용히 틀리기 때문이다.

### C. KRX 수정주가 병렬 적재 (권장, 계정 필요)
`stock_history`에 `adj_price` 컬럼(또는 `stock_history_adjusted` 테이블)을 **병렬로** 두고 KRX `adjStkPrc=2`를 적재.
- 👍 정답 소스. 배당까지 조정됨. 기존 `price`를 건드리지 않아 **롤백이 자유롭다**.
- 👎 KRX 회원계정 + 세션 유지 운영 부담. 스크래핑 의존은 그대로(오히려 계정 리스크 추가).

**권장: C.** 단 **계정 도입 결정이 선행**이고, 그 전까지는 A(현상 유지 + 백테스트 스크리닝)로 버틴다.

## 4. C안 설계 초안

### 4-1. 스키마 — 병렬 컬럼, 파괴적 마이그레이션 금지

```sql
ALTER TABLE stock_history ADD COLUMN adj_price NUMERIC(12,2);   -- NULL = 미적재
ALTER TABLE stock_history ADD COLUMN adj_source TEXT;           -- 'krx' 등 출처 추적
```

- `price`는 **그대로 둔다**. 덮어쓰면 잘못됐을 때 되돌릴 원본이 없다.
- `NUMERIC(12,2)` — 수정주가는 분할 소급으로 소수가 나온다. 현 `price`가 INTEGER인 게 이미 반올림 손실이다(3.14차 `market_index_history`에서 같은 이유로 NUMERIC을 골랐다).
- `adj_price IS NULL`이면 호출부가 `price`로 폴백 → **적재 진행 중에도 앱이 정상 동작**한다.

### 4-2. 읽기 경로 — SSOT 한 곳

지금 `stock_history.price`를 읽는 곳이 흩어져 있다(`scoring.js` · `history.js` · `portfolio/router.js` 볼래틸리티 · `attention/service.js` · 백테스트 `load.mjs`).
각자 `COALESCE(adj_price, price)`를 쓰기 시작하면 **한 곳만 빠져도 화면 간 숫자가 갈린다** — D차에서 겪은 그 문제다.

→ **읽기 헬퍼 하나**(`server/domains/stock/history.js`에 `selectPriceExpr()` 또는 뷰)로 접고, 전 호출부가 그것만 쓴다.

### 4-3. 무엇을 조정하고 무엇을 안 하나

| 대상 | 수정주가 | 이유 |
|---|---|---|
| 기술지표·SMA·52주 범위·차트 | ✅ | 시계열 연속성이 본질 |
| 백테스트 forward return | ✅ | 왜곡 제거가 목적 |
| **사용자 평단(`avgPrice`)** | ❌ | 실제 체결가다. 건드리면 안 된다 |
| **보유 수량** | ⚠️ 별개 문제 | 분할하면 수량도 변한다 — 사용자가 직접 수정해야 한다(자동 조정은 임의 개입) |

⚠️ **평단·수량은 조정하지 않는데 현재가만 조정하면** 분할 종목의 표시 수익률이 그 순간 왜곡된다.
→ 분할 이벤트가 감지된 보유 종목엔 **"분할이 있었어요 — 보유 수량을 확인해 주세요"** 안내가 필요하다(판단어 없이 사실만).
이건 C안의 필수 동반 작업이지 선택이 아니다.

### 4-4. 적재
`scripts/sync-adjusted-prices.js`(신규) — `backfill-history.js` 패턴. `--dry-run` · `--resume` · 멱등 upsert.
분할 이벤트가 새로 생기면 **해당 종목 전 이력을 재적재**해야 한다(소급 조정이므로 증분이 성립하지 않는다).

## 5. 결정 대기

1. **KRX 회원계정(본인인증) 도입 여부** — C안 전체가 여기 걸려 있다. 계정 정보를 Render 환경변수에 두는 운영 리스크도 함께 판단.
2. 도입 시 차수 분리 — 스키마 → 적재 → 읽기 경로 전환 → 분할 안내 UI, 각각 독립 커밋. 회귀 범위가 넓어 한 번에 하지 않는다.

그때까지: **A안 유지**. 백테스트는 스크리닝으로 방어하고 있고, 라이브 왜곡은 알려진 채로 남는다(2종목/178).
